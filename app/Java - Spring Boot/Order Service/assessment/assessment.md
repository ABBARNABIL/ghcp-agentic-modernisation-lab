## 3. Compatibility Blockers

### BLOCKER-1 — `javax.*` → `jakarta.*` namespace migration (HIGH effort)
**Evidence:**  
- `src/main/java/com/contoso/demo/orderservice/model/Order.java` lines 3–12: imports `javax.persistence.*`, `javax.validation.constraints.*`  
- `src/main/java/com/contoso/demo/orderservice/web/OrderController.java` line 17: imports `javax.validation.Valid`

Spring Boot 3.x moved entirely to Jakarta EE 10. All `javax.persistence`, `javax.validation`, `javax.servlet` imports must be renamed to `jakarta.persistence`, `jakarta.validation`, `jakarta.servlet`.

**Affected files:**
- `src/main/java/com/contoso/demo/orderservice/model/Order.java` (9 javax imports)
- `src/main/java/com/contoso/demo/orderservice/web/OrderController.java` (1 javax import)

**Fix type:** Bulk find-and-replace (`javax.` → `jakarta.` scoped to persistence/validation packages). Can be automated.

---

### BLOCKER-2 — `WebMvcConfigurerAdapter` removed in Spring 6 (LOW effort)
**Evidence:**  
- `src/main/java/com/contoso/demo/orderservice/config/WebConfig.java` line 9: `extends WebMvcConfigurerAdapter`  
- Comment in file: *"Uses the deprecated WebMvcConfigurerAdapter on purpose so the modernization agent has a deprecated-API migration to perform"*

`WebMvcConfigurerAdapter` was deprecated in Spring 5.0 and **removed** in Spring 6.0 (Spring Boot 3.x). The class must extend nothing but implement `WebMvcConfigurer` directly (the interface has default methods since Java 8).

**Fix type:** Remove `extends WebMvcConfigurerAdapter`, add `implements WebMvcConfigurer`. Single-file, ~2 line change.

---

### BLOCKER-3 — Java compiler source/target set to 8 (MEDIUM effort)
**Evidence:**  
- `pom.xml` lines 20-23, 85-88: `<java.version>8</java.version>`, `<source>8</source>`, `<target>8</target>`

Must be updated to `25` (or intermediate steps). Spring Boot 3.x minimum is Java 17. Compiler plugin configuration must change.

**Compatibility check for source code:** The existing source code uses only Java 8 APIs (streams, lambdas, Optional). No Java 9+ module-system declarations (`module-info.java`) exist. The code is structurally compatible with Java 25 with no source changes beyond the javax→jakarta rename.

---

### BLOCKER-4 — H2 1.x → 2.x SQL dialect changes (LOW-MEDIUM effort)
**Evidence:**  
- Spring Boot 2.7.x BOM manages H2 ~2.1.x; Spring Boot 3.x BOM manages H2 ~2.2.x  
- `application.properties`: `spring.jpa.hibernate.ddl-auto=update` and `spring.h2.console.enabled=true`

H2 2.x has breaking SQL compatibility changes (e.g. reserved keyword handling, `AUTO_INCREMENT` vs `IDENTITY`). With `ddl-auto=update` the schema is auto-generated by Hibernate, which should work correctly with the updated Hibernate 6.x included in Spring Boot 3.x. **Validate that the H2 console still works** and that the `DataSeeder` bean continues to populate data after the upgrade.

## 4. Security Vulnerabilities (CVEs)

### CVE-2021-44228 — Log4Shell (CRITICAL, CVSS 10.0)
**Dependency:** `org.apache.logging.log4j:log4j-core:2.14.1`  
**File:** `pom.xml` line 49-51  
**Description:** Remote Code Execution via JNDI lookup in log messages. An attacker who can control any string logged by the application (e.g. user input, HTTP headers) can execute arbitrary code on the server.  
**Affected versions:** log4j-core 2.0-beta9 through 2.14.1  
**Fix:** Upgrade to `log4j-core` **≥ 2.17.1** (2.23.1 is the latest stable). Note: Spring Boot 3.x BOM does **not** include log4j-core by default (Spring Boot uses Logback); this explicit pinned dependency should be **removed** unless log4j is intentionally used. If retained, pin to 2.23.1+.

> ⚠️ **Note in pom.xml:** *"Intentionally pinned to a vulnerable version for CVE remediation exercises. Do not use in production."* — This confirms the dependency is an intentional exercise artifact.

---

### CVE-2021-45046 — Log4Shell variant (CRITICAL, CVSS 9.0)
**Dependency:** `org.apache.logging.log4j:log4j-core:2.14.1`  
**Description:** Incomplete fix for CVE-2021-44228; certain non-default configurations remain exploitable for RCE.  
**Fix:** Same as above — upgrade to ≥ 2.17.1.

---

### CVE-2021-45105 — Log4j2 DoS (HIGH, CVSS 7.5)
**Dependency:** `org.apache.logging.log4j:log4j-core:2.14.1`  
**Description:** Infinite recursion / stack overflow DoS via self-referential lookups in ThreadContext.  
**Fix:** Upgrade to ≥ 2.17.0.

---

### CVE-2021-44832 — Log4j2 RCE via JDBC Appender (MODERATE, CVSS 6.6)
**Dependency:** `org.apache.logging.log4j:log4j-core:2.14.1`  
**Description:** RCE via attacker-controlled JDBC Appender configuration.  
**Fix:** Upgrade to ≥ 2.17.1.

---

### CVE-2022-42889 — Text4Shell (CRITICAL, CVSS 9.8)
**Dependency:** `org.apache.commons:commons-text:1.9`  
**File:** `pom.xml` lines 53-57  
**Description:** Remote Code Execution via `StringSubstitutor` when processing attacker-controlled strings using `${script:...}`, `${url:...}`, or `${dns:...}` interpolation prefixes. Exploitable if any code path calls `StringSubstitutor.replace()` or `StringLookupFactory` with untrusted input.  
**Affected versions:** commons-text 1.5 through 1.9  
**Fix:** Upgrade to `commons-text` **≥ 1.10.0**.

## 5. Migration Sequencing

The recommended upgrade path is **incremental** to reduce risk and keep the test suite green at each step.

```
Step 1 (CVE remediation — can be done immediately on Java 8 / SB 2.7)
  ├── Remove or upgrade log4j-core to ≥ 2.23.1
  └── Upgrade commons-text to ≥ 1.10.0 (or 1.12.0)

Step 2 (Java upgrade: 8 → 17)
  ├── Update pom.xml: java.version, maven.compiler.source/target → 17
  └── Run full test suite; verify no reflection/access issues

Step 3 (Spring Boot 2.7 → 3.x with Jakarta EE migration)
  ├── Rename javax.persistence.* → jakarta.persistence.*   [Order.java, OrderController.java]
  ├── Rename javax.validation.* → jakarta.validation.*     [Order.java, OrderController.java]
  ├── Replace WebMvcConfigurerAdapter with WebMvcConfigurer [WebConfig.java]
  ├── Update pom.xml Spring Boot version to 3.5.x
  └── Run full test suite; verify H2 console, DataSeeder, all REST endpoints

Step 4 (Java 17 → 25)
  ├── Update pom.xml: java.version, source/target → 25
  ├── Optional: adopt Java 21/25 language features (records, text blocks, sealed classes)
  └── Run full test suite; regression check
```

**Rationale for not jumping directly to Java 25 + SB 3.5 in one step:** The javax→jakarta migration and the compiler upgrade are independent failure modes. Isolating them makes failures easier to diagnose.

## 7. Validation Recommendations

After each migration step:

1. **Compile:** `mvn clean compile` — must produce zero errors.
2. **Unit tests:** `mvn test` — all 4 test classes (12+ test methods) must pass:
   - `OrderServiceUnitTest` (6 Mockito-based unit tests)
   - `OrderRepositoryTest` (4 DataJpaTest slice tests)
   - `OrderServiceTest` (1 SpringBootTest integration test)
   - `OrderControllerTest` (9 WebMvcTest slice tests)
3. **Application startup:** `mvn spring-boot:run` — verify no startup exceptions, H2 console accessible at `http://127.0.0.1:8080/h2-console`, `DataSeeder` inserts seed rows.
4. **REST smoke test:** Verify `GET /api/orders`, `POST /api/orders`, `PATCH /api/orders/{id}/status` respond correctly.
5. **CVE scan:** After dependency changes, run `mvn dependency:tree` and cross-reference against OSV/NVD for any remaining vulnerable transitive dependencies.
6. **Deprecation warnings:** After Java 25 step, build with `-Xlint:deprecation -Xlint:unchecked` and address any new warnings.

## 9. Tooling Limitations

- **Java AppCAT MCP tools** were not available in this session. AppCAT would additionally scan for: JBoss/WildFly-specific APIs, EJB patterns, XML deployment descriptors, and generate a detailed compatibility report with rule-level findings. For this Spring Boot application none of those patterns exist, so the absence of AppCAT does not create gaps in this assessment.
- **Maven was not executed** (build toolchain not confirmed present on the assessment host). Dependency resolution and transitive CVE scanning was not performed via `mvn dependency:tree` or OWASP Dependency-Check. All CVE findings above are for **direct/explicit** pom.xml dependencies only. A full `mvn dependency:tree` + OWASP Dependency-Check run is recommended as part of Step 1.
- **SAST tooling** (SpotBugs, SonarQube) was not run. No runtime analysis was performed.
